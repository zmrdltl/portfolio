# 개발 원칙

구현 속도보다 문제와 완료 조건을 먼저 분명히 하고, 코드·문서·테스트·리뷰가 같은 기준을 따르도록 작업합니다.

AI 도구는 문제 분해와 구현 보조에 활용하되, 요구사항·기술 판단·코드 리뷰·테스트 기준·릴리스 결정은 직접 수행합니다.

## 핵심 원칙

### 1. 현상을 실패 모드와 책임 경계로 나눕니다

느림이나 오류 같은 증상을 하나의 원인으로 단정하지 않습니다. 동시성 경합, 고정 시간창의 대기, API 계약, DB 변경처럼 서로 다른 실패 모드로 나누고, 직접 수정할 범위와 제외할 일을 구현 전에 정합니다.

### 2. 완료 조건을 실행 가능한 계약으로 만듭니다

성공 응답만 확인하지 않고 API 응답 형태, DB 쓰기·읽기, 상태 전이, 예외 흐름을 테스트와 재현 절차로 고정합니다. 변경이 잘못되면 배포 전에 자동 검사나 같은 조건의 재현에서 드러나게 합니다.

### 3. 이관은 기준선·전환·정리로 나눕니다

기존 동작을 기준선 테스트로 먼저 고정하고, 새 구현으로 전환한 뒤, 이전 의존성과 임시 비교 코드를 제거합니다. 코드 diff뿐 아니라 문서, 상태 계약, 마이그레이션, 사용자 흐름, 배포·롤백 기준까지 같은 변경으로 검토합니다.

## 작업 흐름

```text
도메인과 요구사항 확인
-> 문제, 제외 범위, 완료 조건 정의
-> 구현 계획과 검증 방법 작성
-> 작은 단위로 구현
-> 테스트, 리뷰, 문서 동기화
-> 릴리스와 회귀 확인
```
