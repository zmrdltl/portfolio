# 개발 원칙

구현 속도보다 문제와 완료 조건을 먼저 분명히 하고, 코드·문서·테스트·리뷰가 같은 기준을 따르도록 작업합니다.

AI 도구는 문제 분해와 구현 보조에 활용하되, 요구사항·기술 판단·코드 리뷰·테스트 기준·릴리스 결정은 직접 수행합니다.

## 핵심 원칙

### 1. 증상과 원인을 구분하고 수정 범위를 정합니다

느리거나 실패하는 경로를 한 가지 원인으로 단정하지 않습니다. 동시성 경합, 고정 시간창 때문에 생기는 최대 대기 시간, API 응답, DB 변경을 따로 확인한 뒤 직접 수정할 부분과 바꾸지 않을 부분을 정합니다.

### 2. 완료 조건을 테스트할 수 있게 만듭니다

API가 성공했다는 사실만 보지 않습니다. 응답 형태, DB 쓰기·읽기, 화면 분기, 예외 처리를 테스트와 재현 절차로 확인해 잘못된 변경을 배포 전에 찾습니다.

### 3. 라이브러리나 내부 구현을 교체하기 전에 기존 동작을 확인합니다

라이브러리나 내부 구현을 바꿀 때는 현재 동작을 테스트로 먼저 기록합니다. 새 구현으로 바꾼 뒤 이전 의존성과 임시 비교 코드를 제거하고, 영향받는 화면·문서·배포 절차도 함께 확인합니다.

## 작업 흐름

```text
도메인과 요구사항 확인
-> 문제, 제외 범위, 완료 조건 정의
-> 구현 계획과 검증 방법 작성
-> 작은 단위로 구현
-> 테스트, 리뷰, 문서 동기화
-> 릴리스와 회귀 확인
```
