# 개발 원칙

구현 속도보다 문제와 완료 조건을 먼저 분명히 하고, 코드·문서·테스트·리뷰가 같은 기준을 따르도록 작업합니다.

## 핵심 원칙

### 1. 문제와 범위를 먼저 정합니다

기능이 필요한 배경, 사용자 흐름, 운영 정책을 확인한 뒤 해결할 문제와 제외할 일을 나눕니다. 성공 조건과 책임 경계가 분명해야 구현과 리뷰가 같은 목표를 보며, 도구 선택보다 문제 정의가 앞섭니다.

### 2. 완료 조건을 검증 가능하게 만듭니다

핵심 동작과 예외 흐름을 테스트로 고정하고, API 계약·데이터 형태·호환성처럼 회귀 위험이 큰 지점을 별도 확인합니다. 변경이 잘못되면 자동 검사나 재현 절차에서 드러나게 합니다.

### 3. 변경 전체를 검토하고 전달합니다

코드 diff뿐 아니라 문서, 상태 계약, migration, 사용자 흐름, 배포·롤백 기준을 함께 봅니다. 새 복잡도가 문제 해결에 필요한 수준인지 확인한 뒤 릴리스합니다.

## 작업 흐름

```text
도메인과 요구사항 확인
-> 문제, 제외 범위, 완료 조건 정의
-> 구현 계획과 검증 방법 작성
-> 작은 단위로 구현
-> 테스트, 리뷰, 문서 동기화
-> 릴리스와 회귀 확인
```
